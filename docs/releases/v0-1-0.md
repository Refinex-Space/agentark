# AgentArk 0.1.0 发布说明

## 定位

0.1.0 是 AgentArk 首个完整开发基线，冻结四平面架构、Provider 中立 Snapshot/Runtime 契约、AgentScope Java 2.0.2 适配边界、Web 核心产品流和 Java-only 生产拓扑。它用于可重复集成、评审和目标环境验收，不是托管服务或生产 SLA 声明。

## 主要能力

- Organization/Project/Environment、RBAC、Service Account、API Key 与 Secret Metadata/Binding。
- Prompt、Model、MCP、Skill、Knowledge、Profile、Policy 的不可变版本与审计引用。
- Agent Draft 验证、Canonical Snapshot、Publish、Deployment、Promote 与 Rollback。
- Session/Turn/Run、持久 Event、SSE、HITL、Lease/Fencing、取消、恢复和用量治理。
- 持久 Trigger/Job/Attempt、Cron、Webhook、Channel、Retry、Dead Letter 与 Redrive。
- AgentArk Web 的 Govern、Build、Release、Run、Approve、Operate 与 Observe 路由。
- 非 Root 容器、Helm、NetworkPolicy、SecurityContext、Flyway Job、HA、备份恢复、性能和故障演练。

## 兼容性

- Maven 运行依赖：AgentScope Core/Harness `2.0.2`。
- 固定源码审计：`0c61e7494197ded54eefdeaf9bdeb51807beb752`。
- Snapshot Schema：v1；Runtime Event Schema：v1；0.1.0 没有更早 N-1 Schema。
- Java：21；Node.js：24；pnpm：11；MySQL：8.4；Redis：8.10；Qdrant：1.18.3。

## 已知限制

- 真实模型、Embedding、MCP、Channel、Sandbox RuntimeClass 和云 Object Store 依赖部署方 Provider；仓库 E2E 使用确定性 Test Provider，不发起付费外部调用。
- Vault KV v2 Adapter 已实现并测试，但任何目标环境的 Vault/KMS 身份、TLS、Rotation 和审计仍须单独批准；Local Secret Provider 仅允许开发 Profile。
- Helm 默认连接外部 MySQL、Redis、Object Store、Qdrant 和 IdP，不部署生产数据库、向量库或 Secret Manager。
- 本地 kind、k6 和 Restore Fixture 不代表跨区网络、生产数据量、托管服务 SLA 或业务峰值容量。
- Go Aistio 的工具和切换 Runbook 已完成，但真实外部 Cohort 的 Shadow/Cutover 必须由部署方执行；Team、CRD、ASDP 等非核心能力保持 DEFER/REJECT。
- 0.1.0 是首个契约版本，因此只能验证 v1 同版本滚动兼容；v2 出现后必须同时验证 v2 与 v1 的 N/N-1 窗口。
- 镜像签名和 Provenance 只能在真实 Registry Digest 与 GitHub OIDC 上形成；本地镜像 ID 不替代发布证明。

## 升级和回滚

从同一 0.1.0 候选升级时先执行 Expand/Migrate，再滚动四服务，最后执行 Contract；Runtime 与 Scheduler 必须 Drain。应用可回退到仍兼容当前 Snapshot/Event/DB Schema 的旧 Digest，已应用 Flyway 不降级。完整流程见发布、升级回滚和灾难恢复 Runbook。
